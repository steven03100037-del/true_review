## 1. 采集四件（都在 extension/）

### 1.1 评论配图 → `review.images`（字符串数组）

- **DOM 通道**（inject_main.js `scanCommentsDOM` 卡片循环内）：卡片里找相册容器（快照实证 class 前缀 `album--`，V0.1.2 五选择器的 `ALBUM_SEL` 已定义未使用），取容器内全部 `<img>`，`src || data-src`（懒加载兼容）；`//` 开头的补 `https:`。**无 `album--` 时降级**：在整卡范围内找 class 含 `pic`/`img` 的缩略图集合，仍找不到就空数组（不误收商品主图——排除卡外节点）。
- **hook 通道**：接口 JSON 的 `images/pics/photos` 同义键（`RATE_LIST_KEYS` 已映射），保持数组原样。
- 两通道按既有合并逻辑取并集，URL 去重。

### 1.2 追评分离 → `review.append_text`（字符串）

- **hook 通道**：追评 JSON 常见键 `appendFeedback/append/appendContent` 的 `content/rateContent` 类字段——在 `extractReviewFromApi`（同义键提取处）补这些键位。
- **DOM 通道**：天猫把追评渲染在卡片内"追评"标签邻接的独立文本块。**下游先在真实商品页 Console 实证选择器**（快照样本中"追评"字样仅 1 处，不足以定死选择器），实证方法：
  ```js
  document.querySelectorAll('[class*="Comment--"]').forEach((c,i)=>{
    const t=[...c.querySelectorAll('*')].find(e=>e.children.length===0&&/追评|追加/.test(e.textContent||''));
    if(t) console.log(i, t.className, '→', t.parentElement.className, '|', t.parentElement.textContent.slice(0,80));
  })
  ```
  拿到结构后写精确提取（追评文本节点 ≠ 初评 content--），**找不到追评块就留空**，不把追评并进初评 text（宁可丢不可混——两段式展示依赖分离）。

### 1.3 已购 SKU → `review.sku`（字符串）

- `meta--` 文本现有日期正则旁补一条：`/已购[:：]\s*(.+?)\s*(?:$|\n|·)/`，命中即 `sku`（原样保留，不截断清洗）。

### 1.4 评价总数 → `total_declared`（数字，报告级）

- 面板标题形如"用户评价 · 400+"。正则 `/用户评价\s*[·•・]\s*([\d,]+)\+?/` 在评价 tab 区域文本里找，命中取整（去逗号）；找不到为 null。
- 随 END 消息走 meta（`{total_declared}`），不上报到单条 review。

### 1.5 content.js / background.js

- content.js 合并逻辑：`images`（数组并集去重）、`append_text`（DOM 与 hook 均有值时取**更长**者）、`sku`（非空优先）并入去重合并。
- background.js 上报体 reviews 原样透传（确认无字段白名单即可，若有则补列）；`total_declared` 放进上报体 `meta`。
