# V0.1.5 施工小笔：开面板按钮文案兼容 + 日期提取兜底

> 上游：fss（RK鲲鹏T87 商品页 Console 诊断实证）/ 下游：开发 agent
> 前置：V0.1.4 已合入。改动只在新开面板的文案匹配和日期兜底，两处都很小。

---

## 1. 诊断结论（2026-10-15，RK鲲鹏T87 商品页）

1. **不同商品的"查看全部"按钮文案不同**：该商品页实测按钮文本为 **"查看全部评价"**（`DIV.footer--*` 与 `DIV.ShowButton--*` 两处）+ "查看全部问答"。现 `clickSeeAllComments` 只匹配 `"查看全部评论"` → 该商品**面板从未打开**（用户看到的"转到评论"只是 tab 切换）。ATK 商品恰好叫"评论"，RK 叫"评价"——文案随商品/类目变。
2. **该商品评价总数只有 4 条**（页头"用户评价 · 4"），收到 2 条接近正确——验收"百级"必须选 1000+ 评价的商品，评价少的商品收到几条是**正确行为**，不是 bug。
3. 该商品页日期为 **ISO 格式**（2026-08-10），且报告里两条无日期 → 这版卡片结构里 `meta--` 没命中日期元素，需要整卡兜底。扩展 `DATE_RE` 本就兼容 ISO+中文，无需改正则。
4. 该页面 `Comment--` 卡片命中 2 张（预览区 2 条也是同构卡片，V0.1.3 就绪门会被预览区提前放行——6 轮放弃是第二道防线，现状可接受，不另改）。

## 2. 改动（都在 extension/inject_main.js）

### 2.1 clickSeeAllComments 文案兼容

现匹配行：

```js
      if (t.indexOf("查看全部评论") !== -1 && t.length < 24) {
```

改为：

```js
      if (/查看全部评[论价]/.test(t) && t.length < 24) { // 文案随商品/类目变："评论"或"评价"（V0.1.5 实证两种都有）
```

（函数名与注释里的"评论"字样不必改，行为兼容即可。）

### 2.2 日期提取兜底

`scanCommentsDOM` 精确路径里，`metaText.match(DATE_RE)` 之后补一行：meta 未命中时用整卡文本再找一次：

```js
      var dm = metaText.match(DATE_RE);
      if (!dm) { dm = (el.textContent || "").match(DATE_RE); } // 部分商品卡片日期不在 meta-- 里（V0.1.5 实证），整卡兜底
```
