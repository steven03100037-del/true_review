# V0.1.4 施工小笔：修复页面加载即自动收集（幽灵轮）

> 上游：fss（验收截图定位）/ 下游：开发 agent
> 前置：V0.1.3 已合入。本笔改动极小：inject_main.js 删 1 行，content.js 改注释。

---

## 1. 根因（验收截图实证）

V0.1.3 验收仍只出 2 条，且截图显示**面板根本没开**（预览区"查看全部评论"按钮原样在页面上）、Console 只有页面初始加载的 7 条探针（收集期间零新请求）。

链条：content.js 页面 load 后 1s `armHookEarly()` 注入 inject_main（本意=提前装旁听 hook）→ inject_main **首次执行**的代码是 `installHooks(); startCollection();`——装完 hook **顺手把收集也跑了**。此时用户未点扩展、面板未开，这轮"幽灵收集"扫到预览区 2 条 → 6 轮放弃 → END 上报 → **自动弹出 2 条的报告页**。用户之后点扩展跑的第二轮（会点面板、真滚动）即使成功，弹的报告 tab 也排在幽灵轮后面——用户看到的始终是 2 条旧报告。

**此前 V0.1.2/V0.1.3 两轮验收看到的"只有 2 条"，很可能全是幽灵轮的产物。**

## 2. 改动

### 2.1 inject_main.js（核心，删 1 行）

文件头部入口逻辑现在是：

```js
  if (window.__ZHENPING_HOOKED__) {
    startCollection(); // 二次触发：hook 已装好，只重开一轮收集
    return;
  }
  window.__ZHENPING_HOOKED__ = true;
  installHooks();
  startCollection();
```

把**末尾那个无条件 `startCollection();` 删掉**，并留注释：

```js
  window.__ZHENPING_HOOKED__ = true;
  installHooks();
  // V0.1.4：页面加载只装 hook 旁听，不自动收集——收集仅由用户点扩展触发
  //（content.js START_ANALYSIS → 二次注入 → 走上方 __ZHENPING_HOOKED__ 分支进 startCollection）。
```

行为核对（改后）：页面 load → 只装 hook，静默，**不弹任何报告**；用户点扩展 → 二次注入 → `__ZHENPING_HOOKED__` 已真 → `startCollection()` 正常跑全流程。收集入口有且只有用户点击一条。

### 2.2 content.js（仅注释，防后人误读）

`armHookEarly` 上方注释：

```js
  // 页面打开即常驻装好 hook（只装 hook 不收集，V0.1.4）：评价数据若在初始加载时拉取也能被旁听到。
  // 收集流程仅由用户点击扩展触发；inject_main 首次注入不再自动 startCollection。
```
