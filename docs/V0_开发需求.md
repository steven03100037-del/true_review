# 「真评」V0 开发需求文档

> 交付对象：下游开发 agent。本文档是 V0 的完整施工图——严格照做，边界外的事不做。
> 项目根目录：`D:\FSS\true_review`

## 0. 一句话定位

粘贴淘宝商品链接 → 自动抓评论 → 规则过滤水军 → 出一页手机能看的"真实评论报告"。

- **个人家庭使用工具**，不上架、不分发、不做公网部署
- **V0 零 LLM 依赖**：核心功能（抓取/过滤/报告）不调用任何大模型 API
- 使用场景：家用电脑起服务，iPhone 连同一 WiFi 用 Safari 访问

## 1. 环境与硬约束

| 项 | 要求 |
|---|---|
| 平台 | Windows，Python 3.10+ |
| 核心依赖 | fastapi、uvicorn、playwright（Python 版）、pydantic；写入 requirements.txt |
| 服务 | `uvicorn` 绑定 **`0.0.0.0:8000`**（127.0.0.1 手机访问不到） |
| 凭据 | **绝不入库**：`config_local.py` 写入 `.gitignore`；仓库只放 `config_local.example.py` 模板 |
| 红线 | 禁止批量抓取、禁止账号池、禁止并发抓取、V0 只做淘宝一个平台 |
| 其他 ignore | `__pycache__/`、`*.log`、浏览器用户数据目录（如 `pw-profile/`） |

## 3. 后端契约

### API

| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/api/analyze` | POST | `{"url": "<淘宝链接>"}` | 报告 JSON（同步返回；超时上限 120s） |
| `/api/settings/cookie` | POST | `{"cookie": "<cookie字符串>"}` | 保存到 config_local 并返回 ok |
| `/api/health` | GET | - | `{"ok": true}` |
| `/` | GET | - | 服务 `web/index.html` |

### 报告 JSON 结构（前后端对齐，字段名照此）

```json
{
  "product": {"title": "...", "image_url": "..."},
  "grade": "B",
  "rating": {"original": 4.8, "adjusted": 4.2},
  "stats": {"total": 500, "genuine": 310, "suspicious": 137, "gray": 53},
  "reviews": [
    {"id": 1, "text": "...", "date": "2026-09-30", "tags": ["带图", "追评"], "verdict": "genuine"}
  ],
  "suspicious": [
    {"text": "...", "date": "...", "reasons": ["超短模板好评", "与同簇4条高度相似"]}
  ],
  "meta": {"fetched_pages": 5, "fetched_count": 220, "elapsed_sec": 18},
  "error": null
}
```

错误时返回 `{"error": {"code": "AUTH_REQUIRED|NO_RATE_API|TIMEOUT|BAD_URL", "message": "中文提示"}}`。

## 4. 抓取模块 fetcher.py（最险，优先打通）

**流程**：
1. 链接解析：接受 `item.taobao.com` / `detail.tmall.com` / `m.tb.cn` 等淘宝系链接；短链做 302 展开取真实商品 URL；无法识别 → `BAD_URL`
2. 读 `config_local.py` 中的淘宝 cookie 字符串，解析成 cookie 列表
3. Playwright chromium headless：注入 cookie → 打开商品 H5 页 → **监听 network response**，匹配评论数据接口（响应 URL 或 JSON 结构含评价特征：`rateList`/`rate`/`feedback` 类字段）
4. 从命中响应的 JSON 中提取评论：内容、日期、是否带图、是否追评
5. 自动滚动/触发翻页，页间 `sleep 1~2s` 随机，默认收 5 页或 200 条（先到为准，常量可配）
6. 商品标题/主图：页面 OG meta 标签提取

**实现纪律**：
- **禁止自实现 mtop 签名**——签名由页面自身请求自然产生，我们只旁听
- 接口匹配规则、JSON 字段路径**集中成文件顶部常量**（改版时只改常量区）
- 失败模式结构化：页面跳登录 → `AUTH_REQUIRED`；无评论接口命中 → `NO_RATE_API`；超时 → `TIMEOUT`
- 单次分析串行执行；服务内不做并发队列（玩票低频）

## 5. 过滤管线 cleaner.py + filter_heuristic.py（核心资产）

输入评论列表，输出每条 `verdict ∈ {genuine, suspicious, gray}` + 中文 `reasons[]`。

| # | 规则 | 判定 | 理由文案示例 |
|---|---|---|---|
| 1 | 清洗后精确去重 + 空白规范化去重 | suspicious | "重复评论" |
| 2 | 去标点后长度 ≤6 且命中好评词典（很好/不错/可以/还行/好评/满意/棒/一般…） | suspicious | "超短模板好评" |
| 3 | 3-gram shingle + Jaccard ≥0.8 聚簇，簇内 ≥3 条 | 全簇 suspicious | "与同簇N条高度相似" |
| 4 | 同一前后缀模板不同填充词 ≥3 条 | suspicious | "模板化刷单" |
| 5 | 带图 / 追评 / 长度≥15 且含细节词（用了/穿着/吃/个月/质量/大小…） | genuine | "带图实拍"/"追评"/"细节描述" |
| 6 | 其余 | gray（V0 报告单列展示，不自动判死） | - |

**统计聚合**：
- 占比统计；原始均分 vs 仅 genuine 均分（评论无星数时该字段置 null）
- 评级映射（按 suspicious 占比）：≤10%→A，≤25%→B，≤45%→C，≤70%→D，>70%→F；总评论 <20 条 → U（数据不足）
- **所有阈值集中在 `filter_heuristic.py` 顶部常量区**，调参不改逻辑

**单元测试（先写测试后写实现）**：
- `fixtures/comments_fake.json`：真实感评论种子 30 条 + 手编水军样本 20 条（超短好评 8 条、雷同簇 6 条、模板填充 6 条）混排
- `test_filter.py` 断言：水军样本全部命中 suspicious 且理由正确；真实种子不误杀（gray 可接受）；评级映射边界值
- 测试零外部依赖（不碰网、不碰 LLM）

## 6. 前端 web/index.html（单文件，手机 Safari 优先）

**区块**：输入区（textarea 粘贴链接 + 大按钮"分析"）→ 报告区 → 设置区（cookie 导入，默认折叠）。

**报告卡（仿 Fakespot）**：
- 商品标题 + 主图
- 大字母评级：A 绿 / B 蓝 / C 黄 / D 橙 / F 红 / U 灰
- 评分对比：★4.8 → ★4.2（调整分大字号展示；null 则隐藏）
- 占比条三段色：真实 / 可疑 / 边界

**tab 三个**：真实评论（排序：追评 > 带图 > 细节描述 > 普通，每条带标签 chip）| 疑似水军（理由红字）| 数据（meta 信息）

**体验**：viewport meta、字号 ≥16px、按钮 ≥44px 高；分析中显示 spinner + "正在打开商品页抓取评论，约 20-60 秒"；错误码映射人话（AUTH_REQUIRED → "登录已过期，请在下方设置更新 Cookie"并展开设置区）。

## 7. 测试与验收标准

1. `pytest tests/` 全绿（管线测试零外部依赖）
2. 本地起 `uvicorn`：`GET /api/health` 通；`GET /` 出页面
3. 无 cookie 状态下 POST /api/analyze 真实链接 → 返回 `AUTH_REQUIRED`（证明链路通到登录检查）
4. 开发者若自备淘宝 cookie：真实链接冒烟出报告（可选，能做加分）
5. README 写清：起服务三步（含 start.bat 用法）+ cookie 导入教程（浏览器 F12 → Application/存储 → Cookies 复制，给小白级步骤）
