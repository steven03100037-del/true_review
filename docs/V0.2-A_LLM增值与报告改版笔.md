## 0. 本笔范围一句话

backend 实现 LLM 增值三件（灰桶从严终审/打分+维度/划重点）+ 异步管线 + SQLite 三表落库 + 停用自评 grade/rating；report.html 按 mockup 全量改版。扩展侧采集（图片/追评/SKU/总数）是**另一支笔 V0.2-B**，本笔对那些字段只做"透传+展示、缺省不影响"。

## 1. 设计定稿（fss 已拍板）

- **异步轮询**：报告先秒开（规则层结果），LLM 后台跑（约 1 分钟），前端每 4s 轮询自动刷新；**问评论（LLM-E）二期不做**
- **过滤口径=从严判真**（fss："看着水的一律归水军，真实池不干净页面做得再漂亮也白做"）：AI 终审只把**明确有真实使用信息**的判 genuine；模板化/空泛/引导话术/**拿不准的一律 suspicious**。边界区从此消灭（全部归入两桶）
- **默认列表=AI 价值排序**：真实池按信息量分降序，最有价值/最丰富的置顶；上方筛选 chips 供按维度/图/追评过滤（mockup 已如此，照做）
- **评级评分卡整个砍掉**（fss："自己的评分没根据"）：grade(A-F)/rating 均分**停算停输出**；"真实/可疑"计数保留（信任行 + 数据 tab）
- **key 为空 → 全层跳过**：报告回到规则层形态，页面显示"未配置"文案，不报错

## 3. 数据库（backend/db.py 新建，SQLite 单文件）

**为什么三表**：报告回看只是一半——V2 自动化要按商品攒档案（同商品多次采集），二期"问评论"要按商品/维度捞评论。报告全文与结构化行**两份都存**：全文保真、行表供查询。

```sql
-- backend/data/reports.db（目录 .gitignore）
CREATE TABLE IF NOT EXISTS goods (        -- 商品档案：按商品唯一，V2"我的档案"列表直接查它
  goods_id   TEXT PRIMARY KEY,            -- 平台+商品ID 的 sha1[:16]（从 page_url 解析 item id；解析失败用 URL 整串哈希）
  platform   TEXT,                        -- 'tmall' | 'taobao'
  item_id    TEXT, title TEXT, image_url TEXT,
  first_seen REAL, last_seen REAL);
CREATE TABLE IF NOT EXISTS reports (      -- 采集批次：每次点扩展一份
  id TEXT PRIMARY KEY, goods_id TEXT, created REAL,
  total_declared INTEGER, fetched_count INTEGER,
  genuine INTEGER, suspicious INTEGER,    -- LLM 终审后的最终数（终审完成时 UPDATE）
  llm_status TEXT, elapsed_sec REAL,
  data_json TEXT);                        -- 报告全文 JSON（报告页渲染以它为准）
CREATE INDEX IF NOT EXISTS idx_reports_goods ON reports(goods_id, created DESC);
CREATE TABLE IF NOT EXISTS reviews (      -- 逐条评论：为二期"问评论"与跨商品分析铺路
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  report_id TEXT, goods_id TEXT, review_no INTEGER,     -- report 内序号（对应报告 JSON reviews[].id）
  text TEXT, append_text TEXT, date TEXT, sku TEXT,
  images_json TEXT, tags_json TEXT,
  verdict TEXT, score INTEGER, dims_json TEXT,          -- LLM 终审/打分后回写
  dup_key TEXT);                                        -- cleaner 的文本指纹（先存备用，本期不做跨报告去重）
CREATE INDEX IF NOT EXISTS idx_reviews_goods ON reviews(goods_id);
```

**写入时机**：ingest 时写 goods（INSERT OR UPDATE last_seen/title/image）+ reports（终审前行：llm_status=pending）+ reviews（规则层结果）；**LLM enhance 完成时 UPDATE**：reports 的 genuine/suspicious/llm_status/elapsed + data_json 全文、reviews 的 verdict/score/dims。db.py 提供函数式接口（`save_ingest` / `update_llm_result` / `get_report_json` / `list_reports_by_goods` 预留），api.py 不直接写 SQL。

## 4. backend/api.py

1. **ingest**：规则层照旧 → 报告**不再写 grade/rating**；顶层 `llm: {"status": "pending"}`（key 缺则 `"skipped"`，不建库不跑线程）；写库（§3）→ enabled 时 `threading.Thread(target=enhance_report, daemon=True).start()`；返回 report_id 不变
