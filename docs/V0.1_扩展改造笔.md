# 「真评」V0.1 改造笔：数据入口切换为 Chrome 扩展

> 交付对象：下游开发 agent。本笔是 V0 的一次架构改造，V0 其余部分（过滤管线/报告/测试）全部保留复用。
> 前置阅读：docs/V0_开发需求.md（V0 契约与本笔的兼容基线）

## 0. 为什么改（背景，一句话）

真实环境验证结论：天猫按"浏览器环境可信度"分级下发评价模块——后端 Playwright 无头浏览器（含 Edge 真指纹/有头/扫码登录/克隆档案+原 cookie 共 6 种组合）全部被静默降级（页面无评价模块）；唯一能看到评价的环境是**用户日常使用的 Chrome**。

**结论**：抓取载体从"后端 Playwright"切换为"用户 Chrome 里的扩展"——页面渲染出什么，扩展就拿什么，天然绕过环境校验。

## 1. 架构变化

```
旧（已废弃）：web → /api/analyze → fetcher.py(Playwright) → 天猫页
新：扩展(content+inject script) 在天猫商品页内旁听评价接口 → POST /api/ingest
    → 后端复用过滤管线 → 存报告 → 扩展开报告页 /report.html?id=xxx
```

- `backend/fetcher.py`：**保留文件不删除**，顶部加注释标注"已废弃（天猫环境降级，见 V0.1 笔），保留供未来对策"，从调用链摘除
- `backend/api.py`：`/api/analyze` 保留（兼容），新增 `/api/ingest` 与 `/api/report/{id}`

## 2. 目录新增

```
extension/
  manifest.json       # MV3
  popup.html/.js      # 扩展按钮弹窗：说明文字 + 「开始分析」按钮 + 状态区
  background.js       # service worker：接收消息、开报告 tab
  content.js          # content script（isolated world）：桥接与流程控制
  inject_main.js      # 注入 MAIN world：hook XHR/fetch + 滚动翻页 + 评论提取
web/
  report.html         # 新增：报告展示页（渲染逻辑从 index.html 抽取复用）
```

## 3. 扩展规格（MV3）

**manifest.json 要点**：
- `"manifest_version": 3`
- `content_scripts`：matches `https://detail.tmall.com/item.htm*`、`https://item.taobao.com/item.htm*`，js: content.js
- `web_accessible_resources`：inject_main.js（供 MAIN world 注入）
- `permissions`: `scripting`, `tabs`；`host_permissions`: `http://127.0.0.1:8000/*`
- action.default_popup: popup.html

**交互流程**：
1. 用户在天猫/淘宝商品页点扩展图标 → popup 显示「开始分析」按钮
2. 点击 → popup 通过 `chrome.tabs.sendMessage` 通知当前页的 content.js
3. content.js 用 `chrome.scripting.executeScript({world:'MAIN', files:['inject_main.js']})` 注入 hook 脚本
4. inject_main.js（MAIN world，页面上下文）：
   - hook `XMLHttpRequest` 与 `fetch`，旁听所有响应
   - 自动点击文本为「用户评价」的 tab（存在才点）
   - 循环滚动触发懒加载，从命中响应中提取评论（字段见 §5）
   - 终止条件（与 V0 修复后的语义一致）：连续 3 轮无新评论 / 达 200 条 / 60s 超时，任一满足即收工
   - 每收集到新数据，`window.postMessage` 推给 content.js
5. content.js 汇总 → `chrome.runtime.sendMessage` 发给 background.js
6. background.js `fetch('http://127.0.0.1:8000/api/ingest', ...)` POST 数据 → 拿 report_id → `chrome.tabs.create` 打开 `http://127.0.0.1:8000/report.html?id=<report_id>`

**提取规则**（inject_main.js 顶部常量区，集中可改）：
- 响应匹配：JSON 递归查找列表键 `rateList | rateInfo | rateDetailList | feedbackList | rateVO`
- 单条字段：内容 `content | rateContent`；日期 `date | rateDate | created`；图片 `images | pics | photos`（非空→tags 加"带图"）；追评 `append | appendComment | isAppend`（真→tags 加"追评"）；星数 `star | rateStar | score`
- 文本去重：同文本只收一条

**失败与状态提示**：popup 状态区实时显示（"已收集 N 条…"/"60 秒超时，返回已收集部分"/"未检测到评价数据"）。超时/零数据同样 POST（后端按现有统计逻辑处理：零评论返回 U 或空报告，不报 500）。

## 4. 后端新增

**POST /api/ingest**
```json
请求: {"product": {"title": "...", "image_url": "..."}, "page_url": "...",
       "reviews": [{"text": "...", "date": "...", "tags": ["带图"], "star": 5}]}
响应: {"report_id": "r_a1b2c3"}
```
- 后端执行：cleaner.clean_reviews → filter_heuristic.filter_reviews → summarize → 组装与 V0 完全同构的报告 JSON → 存入内存 dict `_REPORTS[report_id]`（uuid4 hex 前 8 位，带 `r_` 前缀）
- 内存上限 50 份，超出淘汰最旧（玩票足够）

**GET /api/report/{report_id}**：返回报告 JSON（结构同 V0 第 3 节），不存在返回 404 JSON。

**web/report.html**：读取 `?id=` → fetch `/api/report/<id>` → 渲染。渲染代码从 index.html 的 `renderReport` 抽取复用（index.html 保留原样不动，报告页是它的子集功能）。meta 区新增一行"来源：浏览器扩展"。

## 5. 测试要求

- 新增 `tests/test_ingest.py`：用 fastapi TestClient——POST 一组混合评论（复用 fixtures 的 seeds+spam）→ 200 且有 report_id → GET /api/report/<id> 断言 stats/grade/评分对比正确；GET 不存在 id → 404
- 原有 14 个测试必须保持全绿（管线零改动是硬要求）
- 扩展无法自动化测试，验收走 §7 真实流程

## 6. 明确不做（V0.1 边界）

iOS 快捷指令 / 淘口令解析 / LLM 调用 / DOM 解析兜底方案（记录 TODO：接口旁听失败时的 DOM 兜底留给 V0.2）/ 多用户 / 公网 / 扩展上架（用"加载已解压的扩展程序"开发者模式安装）。

## 7. 验收流程（交付后由项目所有人执行）

1. Chrome 打开 `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」→ 选 `extension/` 目录
2. 打开已验证有评价的商品页（如 `https://detail.tmall.com/item.htm?id=1063884940625`）
3. 点扩展图标 → 开始分析 → 等待自动收集 → 自动弹出报告页
4. 断言：报告含真实评论（非空）、评级/占比合理、疑似水军附理由
5. 对照浏览器里肉眼可见的评价列表，抽查 5 条过滤判定是否符合直觉

## 8. 凭据与红线

- 扩展与后端均无凭据（天然免维护——不再需要导入淘宝 Cookie）
- 红线不变：单机、低频、无批量、不上架、不分发扩展包给他人
- 自检报告追加 V0.1 章节：改动清单 + pytest 结果
