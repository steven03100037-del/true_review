## 6. 修复记录

### 2026-10-14 翻页循环阻塞级缺陷（reviewer 提出）

**问题**：`_fetch_with_browser` 翻页循环中 `no_new_rounds` 只在 `len(raw_reviews)==0`
时递增，且 break 限定 `rate_hits==0`。已抓到部分评论后滚动不再产生新响应时，
while 三条件恒真，空转到 120s deadline 抛 TIMEOUT，已抓评论全部丢弃——
评论不足 5 页/200 条的商品（大多数）都无法正常返回。

**修法**（提交于 fix/fetch-collect-loop 分支，合入 main）：
1. 每轮记录 `prev_count`，滚动等待后比较：无增长 → `no_new_rounds += 1`，
   有增长 → 归零；
2. `no_new_rounds >= NO_NEW_ROUNDS_GIVEUP` 即 break，删除 `==0 才计数、
   rate_hits==0 才 break` 的限定；
3. 循环内 `expired()` 由 raise 改为 break；收尾时已有数据则正常返回并在
   `meta` 附加 `truncated_by_timeout: true`（api 透传、前端数据 tab 展示），
   为空才 raise TIMEOUT；
4. 终止判定抽成纯函数 `_should_stop_collecting(rounds_no_new, rate_hits,
   review_count, *, max_pages, max_reviews)`，新增 `tests/test_fetcher.py`
   三条回归断言（giveup 轮数即停 / 有新评论继续 / 达条数上限即停）。

**验证**：`py_compile` 过；`pytest tests/` 14 passed（11 原有 + 3 回归）。
